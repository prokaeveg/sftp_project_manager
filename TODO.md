## P1 — надёжность и проверяемость

- [ ] **Защитить portable-данные от одновременного запуска нескольких экземпляров.**
  Основание: README прямо отмечает отсутствие поддержки, `main.go` не задаёт single-instance guard; `internal/config/store.go` сохраняет общий settings.json и резервную копию. Риск — конкурирующие сохранения, а не доказанная порча в проведённых тестах.
  Готово, когда второй процесс для того же каталога data не получает право записи и показывает понятное сообщение; разные portable-каталоги независимы. Проверить на временных каталогах, включая аварийное завершение первого процесса.

- [ ] **Подтверждать закрытие приложения при незавершённой очереди.**
  Основание: `main.go` вызывает Shutdown при выходе, но не содержит OnBeforeClose; очередь хранится только в памяти (`internal/application/queue.go`, README).
  Готово, когда пользователь видит число активных/ожидающих заданий, может продолжить работу либо явно отменить и выйти; завершение не зависает и не выдаёт частичную передачу за успешную. Автоматически возобновлять передачи после запуска не нужно.

- [ ] **Восстановить воспроизводимые UI-проверки и единый контроль перед релизом.**
  Подтверждено: Makefile и README ссылаются на `scripts/verify-phpstorm-ui.mjs`, `verify-file-comparison-ui.mjs`, `verify-git-ui.mjs`, `verify-copy-paths-ui.mjs`, но этих файлов в рабочем дереве нет. Текущие frontend-тесты проверяют вспомогательные модули, а не Vue DOM.
  Готово, когда проверки доступны из чистого checkout и покрывают создание/импорт проекта, несколько серверов, выбор назначения, подтверждение перезаписи, отмену, ошибки подключения и сравнение только для чтения. Добавить Windows CI либо эквивалентный единый локальный сценарий: vet, Go/frontend tests, frontend build, UI smoke и `scripts/build.ps1`; проверить состав архива без data.

- [ ] **Устранить неоднозначность импорта PhpStorm при дубликатах XML-записей.**
  Подтверждено в `internal/application/phpstorm.go`: `pathsByName[p.Name]` и `sshByID[c.ID]` перезаписывают предыдущую запись, а сервер отмечается seen до валидации. При невалидном первом сервере второй одноимённый уже пропускается.
  Готово, когда неоднозначные mappings/SSH ID/серверы и повторные PublishConfigData диагностируются явно; результат не выбирает молча последнее назначение. Добавить fixtures с перестановкой записей, неверной первой записью и различающимися mappings. Сохранить отсутствие сетевых действий и импорта секретов.

## P2 — удобство, внешний вид и сопровождение

- [ ] **Провести визуальную полировку основных сценариев на Windows.**
  Это предложение по качеству, не утверждение о найденных визуальных дефектах. Основа: `frontend/src/style.css`, App.vue и компоненты workspace.
  Проверить 960×640 и большие окна, DPI 100/125/150/200%, длинные русские названия и пути, много вкладок, пустые/ошибочные/загружаемые состояния. Унифицировать отступы, размеры кнопок, типографику, контраст и видимый фокус. Сделать проект, сервер и направление передачи легко различимыми. Готовность подтверждать снимками до/после и прохождением сценариев, а не только сборкой.

- [ ] **Довести клавиатурную навигацию и доступность деревьев.**
  Основание: `frontend/src/components/FileTree.vue` содержит treeitem, но полная семантика tree/group и стандартная навигация требуют доработки.
  Готово, когда дерево проходится стрелками, Home/End, раскрывается/сворачивается без мыши, корректно сообщает выбор и раскрытие; фокус возвращается после диалогов и закрытия вкладок. Добавить DOM-тесты, отдельно проверить поиск при пустом ответе и быстрых сменах запроса.

- [ ] **Унифицировать русский язык и терминологию интерфейса.**
  Подтверждённые примеры смешения: `Unversioned files` в App.vue, `Mark directory excluded` в пользовательском сценарии README. Проверить остальные строки, включая технические ошибки Go.
  Готово, когда пользовательские действия и ошибки изложены по-русски, одинаковые операции называются одинаково, а исключение из поиска явно отличается от запрета передачи. Сохранить понятные технические имена SFTP/Git.

- [ ] **Добавить управляемое восстановление настроек из резервной копии.**
  Основание: `internal/config/store.go` создаёт settings.json.bak, но Load читает только основной файл. Это улучшение восстановления, не обнаруженная потеря данных.
  Готово, когда при повреждении JSON можно проверить и явно восстановить корректную копию, сохранив повреждённый оригинал; ошибки версии схемы и прав записи объясняются отдельно. Тестировать только на временных данных.

- [ ] **Сделать импортированные исключения заметным этапом проверки проекта.**
  Основание: `phpstorm.go` предупреждает, что исключения PhpStorm не перенесены, и задаёт стандартный набор. Предложение: показать различие правил до первой передачи; поддерживаемые правила переносить только после проверки эквивалентности семантики.
  Готово, когда пользователь видит пропущенные правила и может настроить исключения до передачи; непредставимые правила не превращаются молча в более широкие разрешения.

- [ ] **Проверить производительность на больших проектах и длинных планах передачи.**
  Основание: App.vue выводит строки плана через v-for, FileWorkspace.vue может отображать до 10 000 строк. Фактические задержки пока не измерены.
  Сначала измерить дерево, поиск, Git, diff и план на синтетических наборах; затем при необходимости внедрить виртуализацию/порционную отрисовку. Зафиксировать размеры наборов, время отклика и потребление памяти, сохранить выбор и клавиатурную навигацию.

- [ ] **Разделить ответственность App.vue без изменения поведения.**
  Основание: около 826 строк объединяют настройки, импорт, Git, авторизацию, очередь и навигацию; часть обращений идёт прямо через window.go вместо единого bridge.
  Выносить связные контроллеры и диалоги постепенно после UI-тестов. Централизовать типизированный доступ к Wails в `frontend/src/bridge.ts`; заменить глобальные DOM-поиски локальными refs там, где они управляют фокусом. Генерируемые wailsjs вручную не менять.

## P3 — усиление гарантий и расширения

- [ ] **Определить дополнительные гарантии консистентности передачи.**
  Подтверждённое ограничение `internal/transfer/transfer.go`: сравниваются тип/режим, размер и mtime; это не доказательство равенства содержимого. README уже описывает ограничения.
  Добавить тест одинакового размера/mtime при изменённом содержимом; оценить стоимость проверки хеша/идентичности открытого локального файла и доступные гарантии SFTP. Не обещать абсолютную защиту от конкурентных изменений на произвольном сервере.

- [ ] **Уточнить границы чтения файлов импорта PhpStorm.**
  `readIdeaXML` открывает фиксированные пути через os.Open, который следует по ссылкам. Решить и документировать политику для ссылок/junctions и нестандартных файлов внутри .idea; добавить соответствующие тесты и понятный отказ для неподдерживаемых случаев. Это read-only импорт, а не подтверждённая запись вне проекта.
