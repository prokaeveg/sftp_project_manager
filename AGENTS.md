# Правила работы в проекте

## Проект и архитектура

- Это portable-приложение для Windows: Go, Wails v2, Vue 3 и TypeScript. Основной язык интерфейса и общения с пользователем — русский.
- `app.go` — тонкий мост Wails; бизнес-логика находится в `internal/application` и профильных пакетах `internal/`.
- `frontend/src/bridge.ts` описывает контракт frontend с Go. При изменении API обновляйте обе стороны. Генерируемые `frontend/wailsjs` не редактируйте вручную.
- Следуйте существующим компонентам и стилям; ограничивайте изменения текущей задачей.

## Данные и поведение

- Поддерживаются несколько проектов и серверов. Не привязывайте действия к первому серверу или единственному remote с именем `origin`.
- У сервера есть корень просмотра, у маппинга — локальный путь и deployment относительно серверного корня. Просмотр удалённого дерева и пути передачи имеют разные границы.
- Сохраняйте проверки путей, исключений, симлинков/junctions, коллизий регистра и допустимости Windows-имён.
- Предпросмотр и сравнение файлов выполняются только для чтения. Git-сравнение не должно переключать ветку или автоматически выполнять fetch.
- Сетевые подключения, передачи и перезапись должны сохранять существующий порядок явных действий и подтверждений в интерфейсе.
- Настройки и WebView2-данные находятся в `data` рядом с exe. Не удаляйте пользовательские данные и не включайте их в релизный архив. Пароли и ключи не записывайте в JSON или логи.
- Для тестов используйте временные репозитории, файлы и тестовые подключения; не изменяйте пользовательские репозитории и серверы.

## Проверки

- Перед изменениями изучите `git status` и сохраняйте существующие пользовательские изменения.
- После изменения Go-кода выполняйте `gofmt` для изменённых файлов.
- Основные проверки: `go vet ./...`, `go test ./... -count=1`, `npm --prefix frontend test`, `npm --prefix frontend run build`.
- Для новых функций и исправлений добавляйте содержательные тесты. Для затронутых UI-сценариев используйте подходящие проверки из `scripts/verify-*.mjs`, если они доступны.
- Проверяйте `git diff --check` и итоговый diff. Храните текст в UTF-8, проверяйте русские строки после записи через PowerShell.
- Не утверждайте, что тесты, ручная UI-проверка или сборка выполнены, без фактического результата. Сообщайте о непроверенных сценариях и блокировках.

## Обязательная пересборка после задачи

- После каждой задачи, меняющей код приложения, **обязательно пересобирайте бинарник через `scripts/build.ps1`**, прежде чем сообщать о завершении. Сборки только frontend недостаточно: Wails встраивает его в exe.
- Из корня проекта: `.\scripts\build.ps1`.
- Если выполнение скриптов запрещено, используйте отдельный процесс: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1`. Не меняйте системную политику выполнения.
- Скрипт собирает Windows amd64 через Wails v2.16.0 с `-webview2 error` и упаковывает только exe и README.
- Проверьте успешный код завершения и актуальность файлов `build/bin/sftp-project-manager.exe` и `dist/sftp-project-manager-windows-amd64.zip`.
- Если сборка не прошла, устраните причину в рамках задачи либо явно сообщите о блокировке. Не выдавайте старый бинарник за результат текущих изменений.
- Генерируемые exe, архивы, `frontend/dist`, `frontend/wailsjs`, зависимости и `data` не добавляйте в Git. Не меняйте `.gitignore` ради включения этих артефактов.
- Не создавайте коммиты и не отправляйте изменения в remote без запроса пользователя.
