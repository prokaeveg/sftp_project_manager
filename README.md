# SFTP Project Manager

Portable-приложение: Go + Wails v3.1.0 + Vue 3 + TypeScript. Поддерживает несколько проектов и подключений. У каждого сервера есть корень просмотра, а маппинги связывают локальные папки с каталогами относительно этого корня; удалённое дерево можно просматривать вне маппингов, передача идёт по выбранному маппингу. Есть локальное/удалённое дерево, множественный выбор и рекурсивная передача папок с общим предпросмотром и подтверждением перезаписи.

Рабочее окно устроено по модели PhpStorm: полный локальный проект слева, сервер справа. При первом запуске создайте проект только с локальной папкой; серверы добавляются позже в отдельном окне настроек. Первый сервер становится сервером по умолчанию, выбор можно изменить.

При выборе другого проекта появляется диалог «В этом окне / В новом окне / Отмена». Отмена и Escape оставляют текущий проект без изменений. Проект, уже открытый в другом окне, поднимается на передний план вместо создания копии. Название проекта видно в заголовке Windows.

У каждого окна свои выбранный сервер и маппинг, подключения, очередь и диалог авторизации. Закрытие окна завершает только его операции; приложение выходит после закрытия последнего окна. Каталог проектов общий: изменения сохраняются последовательно и становятся видны в остальных окнах при возвращении к ним. Создание нового проекта по кнопке «Новый проект» по-прежнему выполняется в текущем окне.

Локальную папку проекта можно указать вручную или выбрать кнопкой «Обзор…» через стандартный диалог Windows. Выбор заполняет форму; проект сохраняется отдельной кнопкой. Отмена диалога сохраняет прежний путь.

В режиме SSH-алиаса кнопка «Прочитать SSH-алиасы» читает пользовательский либо указанный конфиг и Include без выполнения команд. Выбор имени заполняет черновик. Отдельная «Проверить эффективные настройки» использует `ssh -G` после подтверждения доверия: `Match exec` при такой оценке может выполнять команды. Проверка ограничена 15 секундами; под Windows отмена завершает дерево её процессов.

## Копирование путей

В ПКМ по файлу или папке доступны «Копировать полный локальный путь», «Копировать путь относительно проекта» и «Копировать путь на <сервер>». При нескольких серверах отдельное подменю позволяет выбрать сервер назначения. При множественном выборе пути копируются по одному на строку.

В локальном дереве серверный путь вычисляется через маппинг сервера по умолчанию. В удалённом дереве прямое копирование серверного пути использует просматриваемый сервер и работает даже вне маппингов; для локального/проектного пути или другого сервера необходим маппинг исходного сервера. Пути определяются без подключения и передачи файлов. Если хотя бы один путь невозможно сопоставить, буфер обмена не заменяется. Копирование доступно и для исключённых элементов; передача для них остаётся заблокированной.

## Git-статусы и изменения

Если локальная папка находится в Git-репозитории и `git` доступен в PATH, имена файлов окрашиваются: неотслеживаемые — красным, игнорируемые Git файлы и папки — коричневым, добавленные в индекс Git — зелёным, изменённые — синим, неизменённые — белым. Удаления и конфликты обозначаются красным и текстовой меткой. Папки отражают статус вложенных файлов; игнорируемые файлы не считаются неотслеживаемыми.

На внешней левой панели доступны кнопки с иконками «Проект» и «Изменения»; подсказки показывают их назначение, стрелки вверх/вниз переключают панели. Панель действий слева появляется плавно при наведении на область проекта и скрывается вне неё; при клавиатурном фокусе кнопки также доступны. Порядок: загрузка на сервер, снятие выбора, обновление Git, компактный прицел. В «Изменениях» обновление перечитывает только Git-статус. Путь проекта показан справа от корневой папки в дереве, длинный путь обрезается; при наведении или фокусе обрезанный путь продолжается на той же строке поверх области просмотра, сохраняя шрифт и цвет, без отдельной подсказки. Кнопка с прицелом показывает открытый файл в дереве: переключает на «Проект», раскрывает папки, выделяет строку и прокручивает её в видимую область. Если файл не открыт, используется единственный выбранный локальный элемент. Для удалённой вкладки локальный путь определяется через mapping её исходного сервера. Во второй основной список содержит только изменения отслеживаемых файлов. Неотслеживаемые файлы, не попавшие в Git ignore, вынесены в отдельную сворачиваемую группу «Unversioned files» и выделены красным; в дереве проекта они также красные. Игнорируемые Git элементы окрашены коричневым только в дереве проекта и не входят ни в одну группу изменений. Кнопки «Список» и «Дерево» переключают вид. Двойной клик или Enter открывает существующий файл, ПКМ позволяет сравнить его с сервером. Удалённые файлы показаны для информации. Папки в дереве изменений группируют файлы: для передачи выбирайте сами файлы.

Статус обновляется раз в 5 секунд, при переключении проекта, открытии вкладки «Изменения» и кнопкой обновления. Если Git отсутствует или репозиторий недоступен, отображается пояснение; обычное дерево продолжает работать. Чтение ограничено 10 секундами, 8 МиБ на команду и 100 000 файлов. Оно не добавляет файлы в индекс, не создаёт коммиты и не обращается к серверу Git.

## Импорт одного проекта PhpStorm

При создании нового проекта укажите папку самого проекта (с `.idea`), включите «Импортировать настройки одного проекта PhpStorm» и нажмите «Прочитать настройки PhpStorm». Можно выбрать и саму папку `.idea`. Импорт не обходит родительскую папку и не ищет другие проекты.

Проверьте серверы, корни и mappings в предпросмотре, отметьте нужные серверы и нажмите «Создать проект». SSH-алиасы из OpenSSH config по умолчанию не выбраны: их использование нужно подтвердить выбором сервера. Название можно изменить перед сохранением. Отмена не записывает настройки; существующий проект с той же папкой или названием не заменяется.

Поддерживаются project-level `.idea/deployment.xml`, `webServers.xml` и `sshConfigs.xml`, SFTP, ручные SSH-параметры и ссылки на SSH-конфигурации проекта, `$PROJECT_DIR$` в локальных mappings и путях ключей. Неподдерживаемые или неполные серверы пропускаются с объяснением. Настройки уровня IDE и другие макросы не разрешаются автоматически. Исключения PhpStorm не переносятся: проверьте исключения подключения перед первой передачей. Можно создать проект без серверов и добавить их вручную.

Исходные файлы только читаются. Пароли, passphrase, автозагрузка и доверие ключам не переносятся. Импорт не запускает SSH и не передаёт файлы; подключение выполняется отдельно.

## Разработка

На машине разработчика нужны Go 1.26.5, Node.js 24.13.0, npm и WebView2 Runtime. Зафиксирован Wails v3.1.0; версии frontend в `package.json`/`package-lock.json`; Go-зависимости — в `go.mod`/`go.sum`.

```powershell
.\scripts\build.ps1
go test ./...
go vet ./...
```

Первый запуск `scripts/build.ps1` генерирует bindings и `frontend/dist`, необходимые Go embed при компиляции. Для разработки с Vite откройте два терминала: в первом выполните `npm --prefix frontend run dev`, во втором — `make dev`. Цель `make dev` запускает Go-приложение через `go run .` и направляет его на Vite по `http://localhost:5173`; WebView2 Runtime должен быть установлен.

При установленном GNU Make из корня проекта доступны команды:

| Команда | Действие |
| --- | --- |
| `make vet` | Проверка Go-кода через `go vet ./...` |
| `make test` | Все Go-тесты без использования кеша результатов |
| `make copy-paths-ui-test` | Сборка frontend и проверка меню копирования путей на искусственных данных в headless Edge |
| `make git-ui-test` | Сборка frontend и проверка Git-цветов и вкладки изменений на искусственных данных в headless Edge |
| `make comparison-ui-test` | Сборка frontend и проверка сравнения содержимого через ПКМ на искусственных данных в headless Edge |
| `make phpstorm-ui-test` | Сборка frontend и проверка мастера импорта на искусственных данных в headless Edge |
| `make frontend-test` | Тесты состояния деревьев через Node 22.18+ / 24+ |
| `make check` или `make` | Проверка Go-кода, Go-тесты и frontend-тесты |
| `make build` | Windows x64 exe вместе с frontend в `build/bin/sftp-project-manager.exe` |
| `make dev` | Полное приложение Wails с Go backend и горячим обновлением frontend |
| `make frontend-dev` | Только Vite-сервер frontend через `npm run dev`, без Go backend |

Для разработки с сохранением настроек, выбором папок и SFTP используйте `make dev` и открывшееся окно приложения. В отдельном браузере через `make frontend-dev` мост Go/Wails недоступен, поэтому появляется сообщение «Откройте приложение через Wails».

Перед первым отдельным запуском frontend установите зависимости: `npm --prefix frontend ci`. Адрес локального сервера выводится в терминале; остановка — `Ctrl+C`. `make build` собирает exe; упаковка ZIP описана ниже.

## Сборка Windows x64

Из PowerShell в корне проекта:

```powershell
.\scripts\build.ps1
```

Результат: `build/bin/sftp-project-manager.exe` и `dist/sftp-project-manager-windows-amd64.zip`. Скрипт генерирует bindings закреплённым CLI v3.1.0, устанавливает frontend-зависимости, собирает frontend, затем собирает Windows amd64 exe и включает frontend в бинарник. Он не запускает установщик WebView2.

Если политика PowerShell запрещает запуск `.ps1`, вызовите его в отдельном процессе, не меняя системную политику:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

## Portable-запуск

После распаковки проверьте запуск, выбор локальной папки, подключение к серверу
и передачу тестового файла на своём компьютере.

Распакуйте ZIP в доступную для записи папку и запустите exe. Go и Node.js конечному пользователю не нужны. Для запуска требуется установленный Microsoft Edge WebView2 Runtime; автономный архив с Fixed Version Runtime пока не подготовлен.

Настройки: `data/settings.json`, предыдущая валидная версия: `data/settings.json.bak`, данные браузера: `data/webview2`. Пути вычисляются относительно exe, а не рабочей папки. При ошибке доступа перенесите приложение в папку, доступную для записи. Повреждённый конфиг или неизвестная версия схемы останавливают запуск: сохраните исходный файл и восстановите резервную копию вручную. Автоматического сброса нет.

Проекты сохраняются в `projects` схемы 3. У сервера отдельный `rootPath`, у маппинга — `localPath` и относительный `deploymentPath`. Новый сервер начинается с `/` без маппингов: для передачи добавьте маппинг вручную. Схемы 1 и 2 мигрируют в памяти без изменения назначений; первая запись сохраняет исходник в `settings.json.v1.bak` или `settings.json.v2.bak`. Ключи не копируются, пароли не попадают в JSON; по галочке они сохраняются в хранилище Windows.

## Подключение и передача

1. Создайте проект: название и существующая локальная папка. Он сохраняется в JSON без обязательного сервера; слева автоматически появится дерево проекта.
2. В правой области откройте настройки серверов, добавьте именованное подключение: SSH-алиас из `.ssh/config` либо host/user/port и необязательный абсолютный путь ключа (иначе SSH-agent). Укажите корень просмотра сервера, например `/var/www/html`. Отдельно задайте непересекающиеся маппинги: локальная папка проекта и путь deployment от серверного корня (`.` означает сам корень). При необходимости добавьте серверы и выберите default. Ручной режим не читает пользовательский SSH-конфиг; алиас использует пользовательский или явно выбранный файл.
3. Сохраните настройки. Выберите сервер в заголовке правой панели и явно подключитесь/обновите дерево или раскройте его корень. Слева остаётся полный локальный проект. Вложенные папки загружаются при раскрытии, повторное раскрытие использует кеш. Обновление отдельной папки доступно через ПКМ → «Обновить папку» в локальном и удалённом дереве; иконок обновления в строках папок нет. «Обновить» у папки перечитывает её и сбрасывает вложенные ветки. При старте автоматического SSH нет.
4. Выделите файлы/папки кликом, Ctrl или Shift. Выберите передачу через ПКМ либо быструю кнопку сервера по умолчанию. Папки включают нераскрытые вложенные ветки. Проверьте общий план: сервер, направление, пути, объём, создания папок и пропуски. Существующие файлы пропускаются, пока явно не разрешена перезапись. Включённые `.env`/`.env.*` требуют отдельного подтверждения. Нажмите «Добавить в очередь»; недостающие папки создаются по плану внутри маппинга.
5. Для остановки нажмите «Отменить текущую операцию». Проверьте результаты каждого элемента, затем обновите дерево назначения. Передача может завершиться частично; готовые файлы/папки не откатываются. Для повтора заново выберите нужные файлы и проверьте новый предпросмотр: скрытого повтора нет.

По умолчанию `BatchMode=yes` использует ключ или агент. Для входа по паролю выберите «Пароль» в настройках сервера: приложение запросит его при подключении, без сохранения в конфиге. Галочка «Сохранить пароль» сохраняет успешный ответ в Диспетчере учётных данных Windows для следующих входов, включая перезапуск. Удалить его можно кнопкой «Забыть сохранённый пароль». Зашифрованный ключ пока должен быть доступен агенту; passphrase/MFA требуют отдельной реализации и проверки. На Windows приватный ключ должен иметь права, принимаемые OpenSSH; приложение не меняет его ACL.

Проверка ключа сервера обязательна (`StrictHostKeyChecking=yes`). Неизвестный или изменённый ключ останавливает подключение. Для нового сервера сначала получите ожидаемый отпечаток по доверенному каналу и подтвердите его обычным OpenSSH вне приложения с тем же конфигом и known_hosts. Не принимайте изменённый ключ без проверки. Диалог добавления ключа в самом приложении пока отсутствует. Можно явно выбрать другой абсолютный путь known_hosts; файл не переписывается приложением.

ProxyJump (включая цепочку узлов) и ProxyCommand поддерживаются в режиме SSH-алиаса из исходного доверенного конфига. OpenSSH может выполнять `Match exec` и команды прокси. Под Windows отмена и закрытие приложения завершают созданное дерево процессов через Job Object. Для jump-узлов задайте в конфиге `BatchMode yes`, `StrictHostKeyChecking yes`, проверенный known_hosts, `ControlMaster no` и `ControlPath none`: параметры конечного сервера на них не переносятся.

В проверенном Windows OpenSSH 9.5 ProxyJump некорректно передаёт путь альтернативного конфига с пробелами. Используйте для такого подключения путь конфига без пробелов; ProxyCommand с явно заключённым в кавычки путём проверен отдельно. В portable ZIP инструкция `proxy-connections.md` лежит рядом с exe.

Удалённая навигация лениво открывает отдельную SFTP-сессию и повторно использует её для чтения папок и обновления дерева. Сессия завершается после 10 минут простоя; чтение ограничено 30 секундами, а отмена или таймаут закрывает её. Смена проекта, сервера или конфигурации подключения, а также явное отключение завершают сессию. UI показывает её состояние и позволяет отключить или переподключить сервер. Пакетные передачи используют собственные сессии и блокируют навигацию на время работы; одновременно выполняется одна удалённая операция. Общий предпросмотр ограничен 2 минутами, выполнение пакета — 30 минутами (старый API одиночной передачи — 5 минутами). Предпросмотр хранит снимок параметров профиля и одноразовый токен: последующее изменение профиля не меняет подготовленное назначение. Изменение исключений аннулирует токен. Содержимое внешнего SSH-конфига при этом не замораживается.

Центральная панель открывает локальные и удалённые файлы двойным кликом или Enter. Удалённые вкладки показывают имя сервера и сохраняют его при переключении подключения. В ПКМ по одному файлу есть «Сравнить с сервером <сервер по умолчанию>» и «Сравнить с ▸» для выбора сервера; сравнение использует mappings и не меняет активный сервер. Ctrl+Shift+N ищет файл по имени во всём локальном проекте, включая нераскрытые папки; стрелки выбирают результат, Enter открывает его, Escape закрывает поиск. Предпросмотр только для чтения, UTF-8/UTF-16 с BOM, до 2 МиБ и 10 000 отображаемых строк; бинарные и неподдерживаемые файлы обозначаются.

Передача пишет во временный файл в каталоге назначения и заменяет цель после успешной копии. Удалённая перезапись требует `posix-rename@openssh.com`; удаления оригинала как обходного решения нет. Проверяются тип, размер, mtime и режим существующей цели повторно, а пакетный план проверяет изменения после предпросмотра. Симлинки/junctions не передаются; недопустимые Windows-имена и коллизии регистра отклоняются. Пакеты можно ставить в FIFO-очередь с прогрессом по байтам и элементам, паузой, отменой и повтором выбранных ошибок.

В настройках каждого подключения есть исключения — по одному правилу на строку, пути от корня проекта, синтаксис `*`, `?`, `**`. Они действуют на upload и download: элементы видны с пометкой «исключён», открытие и передача блокируются. Новые подключения предлагают исключения `.git`, `node_modules` и `.env`; старые правила не меняются. После изменения правил сохраните проект и заново подготовьте передачу.

Метаданные не доказывают равенство содержимого и не дают полной защиты от конкурентной замены путей. ACL/владелец цели не сохраняются; для перезаписи сохраняются доступные permission bits. После обрыва SSH удалённый временный файл может остаться — ошибка очистки содержит его путь. Приложение не переподключается ради скрытой очистки или повтора.

Для диагностики без GUI (также создаёт начальные настройки):

```powershell
& .\build\bin\sftp-project-manager.exe --diagnostics
```

## Структура

Файлы и папки можно копировать перетаскиванием между локальным и удалённым деревьями. Перетащите элемент на папку в противоположной панели: подсветка обозначает назначение. Файл или папка с исходным именем попадёт внутрь выбранной папки. Для загрузки используется сервер, открытый в правой панели. Маппинги для перетаскивания не требуются: источник и назначение выбраны явно. После отпускания мыши открывается обычный план передачи; проверьте пути и добавьте его в очередь. Правила исключений, защита файлов окружения и подтверждение перезаписи сохраняются.

Очередь передач хранится в памяти до закрытия приложения.

В ПКМ локальной папки `Mark directory excluded` исключает её поддерево из поиска Ctrl+Shift+N; `Unmark directory excluded` снимает пометку. Настройка сохраняется на уровне проекта. Новые проекты автоматически исключают папки с именем, начинающимся на `.`, на любой глубине; конкретную папку можно вернуть в поиск. В дереве такие папки имеют подпись «исключена из поиска».

- `internal/config`: JSON, версия схемы, временная запись и резервная копия.
- `internal/application`: действия приложения и диагностика, без зависимости от Wails.
- `internal/mapping`: границы путей и Windows-имена.
- `internal/transport`: системный OpenSSH и SFTP поверх stdin/stdout.
- `internal/transfer`: безопасная передача одного файла через временный файл.
- `app.go`: ограниченный мост для Vue.
- `main.go`: запуск окна и portable-пути.
- `frontend/src`: интерфейс Vue/TypeScript.

Запись сначала выполняется во временный файл в той же папке с `Sync`, затем через `os.Rename`. Атомарность замены и устойчивость к отключению питания не гарантируются на всех файловых системах. Для одного portable-каталога работает один процесс с несколькими окнами: повторный запуск exe поднимает существующее окно. Копии приложения в разных каталогах независимы.
