# Рабочее окно проекта

Требования пользователя от 6 октября 2026: рабочее окно по модели PhpStorm, с деревом локального проекта слева и сервера справа. Для оптимизации контекста читать этот документ и затрагиваемые компоненты; историю прежнего интерфейса не перечитывать.

## Первый запуск

На стартовом экране создать проект: название и локальная папка через стандартный диалог Windows или ручной ввод. SSH-параметры не обязательны. Сохранение записывает проект в `data/settings.json`; файлы проекта не копируются. Локальное дерево автоматически читает корень проекта, справа отображается пустая область с предложением добавить сервер.

Проект без серверов корректен: `connections: []`, выбран только `activeProjectID`, `profile` отсутствует. Его можно закрыть, открыть и переключить без SSH. Некорректные корни, ссылки/junctions и повреждённые настройки по-прежнему отклоняются.

## Серверы и настройки

Кнопка настроек открывает отдельное модальное окно с параметрами проекта и списком серверов. Можно добавить несколько серверов, выбрать существующий для редактирования, удалить его из проекта и назначить сервер по умолчанию. Удаление профиля сервера не удаляет удалённые файлы.

Первый добавленный сервер автоматически становится сервером по умолчанию. `Project.defaultConnectionID` сохраняется в JSON. Старые проекты без этого поля при чтении получают первый сервер в памяти; загрузка сама не переписывает файл. Открытие другого проекта без явно указанного сервера выбирает его сервер по умолчанию и первый маппинг. Явно выбранный сохранённый сервер восстанавливается между запусками; сервер по умолчанию также используется как запасной при удалении активного. Если удалён сервер по умолчанию, его заменяет первый оставшийся; можно удалить и последний сервер, получив снова локальный проект.

Сервер задаётся SSH-алиасом или host/user/port с ключом/агентом. Указывается удалённая папка; для обычного сценария локальный маппинг — `.`. Импорт алиасов, отдельная доверенная оценка `ssh -G`, несколько маппингов и исключения доступны в настройках. Серверы и черновые изменения применяются после сохранения; отмена закрывает окно без сохранения.

## Два дерева

Левая панель всегда показывает **полный локальный корень проекта**. Правая панель показывает **Root path выбранного сервера** независимо от маппингов. В её заголовке находятся выбор сервера и команда подключения/обновления. Сохранение серверов показывает их в списке и подготавливает дерево, но само не запускает SSH. Раскрытие удалённого корня или явное подключение читает сервер.

Вложенные папки загружаются при раскрытии; дерево и выбор сохраняют ранее реализованное поведение кеша. Исключения выбранного подключения помечают элементы локального дерева относительно корня проекта. Пока сервера нет, можно просматривать локальные файлы, но передача недоступна.

Маппинг для передачи определяется по выбранным путям. Локальные пути относительны проекту, удалённые — Root path; они переводятся через пары `localPath ↔ deploymentPath`. Папки вне маппингов можно просматривать; передача отклоняется. [Пакетный предпросмотр](batch-transfers.md), подтверждение `.env`/перезаписи и результаты сохраняют свои проверки. Подробности: [root-deployment.md](root-deployment.md).

Рабочее окно занимает доступную площадь, деревья прокручиваются независимо. Формы, диагностика и предпросмотр вынесены из основной области; результаты передачи доступны отдельно. Размер окна по умолчанию — 1280×800, минимальный — 960×640.

## Навигация и проверки

- Данные: `internal/config/store.go`, `internal/application/projects.go`; полный локальный листинг: `ListProjectLocal` в `files.go`/`app.go`.
- UI: `frontend/src/App.vue`, `components`, `style.css`; перевод локальных путей в маппинг — `file-tree.ts`.
- `make check` — Go vet/тесты и frontend-тесты; `make build` — Vue/TypeScript и Windows exe.
- `node scripts/verify-ui.mjs` после frontend-сборки проверяет интерфейс в изолированном headless Edge с **тестовым мостом**, сохраняет PNG в `dist/ui-review`. Это не проверка настоящего диалога Windows, SSH или JSON-хранилища: их проверяют Go-тесты и ручной smoke test. Тестовый мост никогда не добавляется в production-код.
- Реальное окно Wails, рабочая сеть и целевой ноутбук требуют [ручной проверки](smoke-test.md).
