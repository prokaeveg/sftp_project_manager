# Корень сервера и маппинги

В схеме настроек 3 серверное подключение хранит абсолютный POSIX `rootPath` — каталог, который открывается как корень удалённого дерева. Например, `/var/www/html` становится корнем просмотра. Он не зависит от того, какой маппинг выбран. У нового сервера значение по умолчанию `/`, список маппингов пуст; маппинг добавляется вручную. Сервер без маппингов сохраняется и просматривается, но передача требует маппинга. Его активный `mappingID` пуст, вычисленный `Profile` отсутствует.

Каждый маппинг связывает относительный проекту `localPath` с относительным серверному корню `deploymentPath`. Например, `src → public` при `rootPath: /var/www/html` означает локальную папку `<project>/src` и серверную `/var/www/html/public`. Значение `.` у `deploymentPath` означает сам `rootPath`; значение `.` у `localPath` означает весь локальный проект.

Удалённое дерево можно просматривать за пределами всех маппингов. Передача файлов разрешена только там, где путь переводится ровно через один маппинг. При загрузке файл из локальной стороны сопоставляется по `localPath`, при скачивании серверный путь сопоставляется по `deploymentPath`; оба направления сохраняют соответствие относительных путей внутри пары. Текущий пакет передачи по-прежнему ограничен одним маппингом на каждой выбранной стороне.

При загрузке настроек схем 1 и 2 старые абсолютные `remotePath` преобразуются в `rootPath` и относительные `deploymentPath`. Корнем становится общий предок старых удалённых путей, поэтому конечные каталоги назначения сохраняются. Миграция выполняется в памяти при загрузке; первая запись сохраняет резервную копию исходных настроек.
