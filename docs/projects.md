# Проекты, подключения и маппинги

Краткая навигация для продолжения разработки; не заменяет основной план.

## Контракт

Настройки схемы 3 содержат `projects` и активные `activeProjectID`, `activeConnectionID`, `activeMappingID`.

- Проект: `id`, `name`, абсолютный `localRoot`, `connections`, необязательный `defaultConnectionID`. Проект может существовать без серверов (`connections: []`). Первый созданный сервер становится сервером по умолчанию; его можно изменить в настройках.
- Подключение проекта: `id`, `name`, `connection` с параметрами SSH, абсолютный POSIX `rootPath` — корень просмотра на сервере, `mappings`, необязательный `excludes` (контракт: [exclusions.md](exclusions.md)).
- Маппинг: `id`, относительный проекту `localPath` (например `.` или `src`) и относительный серверному `rootPath` `deploymentPath` (например `.` или `public`). Путь назначения вычисляется как `rootPath + deploymentPath`; `.` означает сам `rootPath`.

Пустые ID новых объектов назначает сервис при сохранении; UI может заранее назначить ID новому серверу для выбора default в черновике. `SaveProject` сохраняет весь проект. Новый сервер имеет корень `/` и пустые `mappings`; добавление маппинга — отдельное действие пользователя. `SelectProject(projectID, "", "")` выбирает сервер по умолчанию и первый маппинг, если он есть, без SSH; явные ID выбирают конкретный сервер/маппинг. У локального проекта без серверов активен только project ID, `Profile` отсутствует. У сервера без маппингов активен connection ID, mapping ID пуст, `Profile` отсутствует, просмотр работает. При выбранном маппинге `Profile` содержит `remoteRoot`, вычисленный из `rootPath` и `deploymentPath`, и снимок SSH-параметров. Старым проектам без default назначается первый сервер в памяти без записи при загрузке.

## Поведение

В [рабочем окне](ide-workspace.md) слева всегда полный локальный проект (`ListProjectLocal`), справа дерево начинается от `rootPath` выбранного сервера независимо от активного маппинга. Локальный корень читается автоматически без SSH; сервер читается только явно. Переключение очищает выбор/предпросмотр и перечитывает локальное дерево. Редактирование проекта/серверов вынесено в модальное окно с отдельным черновиком, который можно сохранить или отменить. Для передачи в обе стороны исходный путь переводится между локальным проектом и сервером через маппинги; просмотр разрешён вне маппингов, передача таких путей отклоняется. Текущий выбор передачи должен целиком попасть в один маппинг.

Сервис проверяет все подключения и маппинги проекта. `rootPath` задаёт серверный корень просмотра; внутри одного подключения запрещены пересекающиеся локальные `localPath` и серверные `deploymentPath`, включая совпадение и вложенность. На Windows локальные сравнения учитывают нечувствительность к регистру. Между разными подключениями одинаковые пути допустимы. Ссылки/junctions и выход из корня запрещены существующим mapping-кодом.

Конфигурации схем 1 и 2 мигрируют в память. Для старых абсолютных `remotePath` вычисляется общий предок как `rootPath`, а каждый `deploymentPath` сохраняет прежнее конечное расположение; загрузка не перезаписывает исходный файл. При первой записи после миграции создаётся резервная копия исходных настроек. Удаление папки после сохранения не должно мешать запуску окна; доступ к ней проверяется при операции.

Подробности контракта путей и примеры: [root-deployment.md](root-deployment.md).

## Навигация и границы

`internal/config` — модель и миграция; `internal/application` — сохранение/выбор/валидация; `app.go` — Wails bridge; `frontend/src/App.vue` — черновик и селекторы. Предпросмотр передачи по-прежнему хранит снимок профиля, а не ссылку на активные ID.

Импорт алиасов и отдельная оценка: [ssh-discovery.md](ssh-discovery.md); исключения: [exclusions.md](exclusions.md); прокси: [proxy-connections.md](proxy-connections.md); рекурсивная передача: [batch-transfers.md](batch-transfers.md). Общая очередь пока ожидается. Проверки фиксируются в `verification.md`, ручные сценарии — в `smoke-test.md`.
