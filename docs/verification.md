## Ограничения проверки

- PowerShell блокирует `.ps1` политикой выполнения: `scripts/build.ps1` целиком не запускался. Сборка и упаковка выполнены напрямую теми же основными командами; политика не менялась.
- Отсутствующий SSH проверен на уровне сервиса, отсутствующий WebView2 на реальной машине не проверен.
- Визуальная проверка UI, ручное сохранение через форму, запуск на машине без Go/Node.js и обычным пользователем на рабочем ноутбуке ещё ожидаются: [smoke test](smoke-test.md).
- Совместимость с Windows рабочего ноутбука не подтверждена. Fixed Version Runtime не поставляется.
- SSH, SFTP, маппинги и передача файлов ещё не реализованы и не тестировались.

## Продолжение: 6 октября 2026 года

Предыдущий раздел описывает только проверку этапа 0 на 5 октября. Теперь реализован первый вертикальный срез.

- `go test ./...`: проходят хранилище, сервис, маппинг, transport и transfer. Профиль сохраняется после перезапуска; копия Status не меняет внутренние настройки; предпросмотр сохраняет первоначальный сервер при смене профиля.
- `TestSystemSSHIntegration`: настоящий Windows `ssh.exe`, временный тестовый SSH/SFTP-сервер на loopback, сгенерированный ключ. Проверены авторизация ключом, листинг, бинарный upload/download, отказ перезаписи без согласия, неизвестный и изменённый host key, отказ авторизации, недоступный сервер, отмена и завершение SSH-процесса. Только временный тестовый ключ получает ограниченный ACL через icacls; пользовательские файлы не изменяются.
- `internal/transfer`: бинарная передача, перезапись, сохранение permission bits, очистка временного файла при отмене с ещё доступным соединением, отказ POSIX-перезаписи при отсутствующей серверной extension. Windows helper отдельно проверяет, что неожиданно появившаяся цель сохраняется, когда перезапись не была разрешена.
- `internal/mapping`: границы сегментов, `..`, абсолютные локальные пути, кириллица/пробелы, недопустимые Windows-имена и уже существующие коллизии регистра; Windows junction-тест проходит. Удалённый относительный путь для листинга не проверяет соответствующие локальные компоненты.
- Проверка TypeScript, frontend production build, `go vet ./...` и Wails Windows build проходят. Реальные имена и сигнатуры методов проверены по сгенерированным Wails declarations; ручной `bridge.ts` расширен ими.
- Финальный ZIP содержит exe, README.md, smoke-test.md и verification.md. Release `--diagnostics` из другой рабочей директории завершился с exit 0 и путями `data` рядом с exe.
- Два субагента на `gpt-6-luna` реализовали mapping/transfer; проведено дополнительное ревью транспортного и application-кода. Найденные зависимости удалённого листинга от локальных путей и лишний интервал между проверкой пути и I/O исправлены повторными проверками.

Ограничения: symlink-тесты **пропускаются** из-за отсутствия привилегии создания симлинков на текущем аккаунте Windows (junction-тест выполнен). Отдельного теста настоящего SSH-agent, интерактивного пароля/MFA, ручного UI и рабочего ноутбука нет. ProxyJump/ProxyCommand отключены. Проверки метаданных и путей уменьшают гонки, но не заменяют атомарное сравнение/замену на сервере или Windows handle-based containment. ACL и владелец назначения не сохраняются. При потере соединения очистка удалённого временного файла может завершиться ошибкой; путь включается в ошибку, скрытого переподключения нет.

## Импорт SSH-алиасов: 6 октября 2026 года

Реализовано текстовое обнаружение алиасов с Include и отдельная явная оценка системным OpenSSH. `go test ./...`, `go vet ./...` и Wails Windows production build прошли, включая TypeScript/frontend. Методы `DiscoverSSH` и `EvaluateSSH` сверены со сгенерированным `App.d.ts`.

- `internal/sshconfig`: конкретные положительные алиасы, комментарии/кавычки/назначение через `=`, пробелы/кириллица/обратные слеши Windows, относительные Include от домашней `.ssh`, glob-порядок, циклы, условные кандидаты, предупреждения и лимиты. Чтение не запускает команды.
- `internal/application`: обнаружение не меняет проекты; оценка без подтверждения доверия отклоняется. Оценка использует общую блокировку удалённых операций, отмену, таймаут 15 секунд и ожидание завершения при shutdown.
- `TestEvaluateSystemOpenSSHConfig`: настоящий Windows `ssh.exe`, временные конфиги с Include/пробелами/IdentityFile, выполнение безвредного Match exec при явной оценке, корректные hostname/user/port, ProxyJump и наличие ProxyCommand без текста команды. ACL ограничен только для временных тестовых конфигов; пользовательский `.ssh/config` не изменялся.
- `TestEvaluateWindowsJobReapsChild`: тест сначала ждёт маркер запуска дочернего процесса, затем отменяет родителя и проверяет отсутствие отложенного маркера. `TestEvaluatePreCancelledDoesNotStartProcess` подтверждает отказ запуска заранее отменённой команды.

Два субагента реализовали parser/evaluator; отдельное ревью исправило разбор Windows-путей, условия Include, сборку UTF-16 environment, наследование NUL/pipe-дескрипторов и обработку отмены. ZIP обновлён.

Ограничения на момент этого шага: ручной UI, закрытие окна во время оценки и рабочий ноутбук ещё не проверены. Текстовое обнаружение не воспроизводит все условия OpenSSH; неподдерживаемые Include-подстановки сообщаются предупреждениями. Эффективная оценка с проверенным управлением дочерними процессами доступна только под Windows. Подробный контракт: [ssh-discovery.md](ssh-discovery.md). Поддержка прокси для SFTP добавлена следующим шагом ниже.

## ProxyJump и ProxyCommand — 6 октября 2026

Выполнены `go test ./... -count=1 -timeout=90s`, `go vet ./...` и production Wails build под Windows amd64 (включая TypeScript/frontend).

- `TestProxyIntegration`: настоящий Windows OpenSSH 9.5p2, два изолированных SSH jump-узла, конечный SSH/SFTP-сервер; листинг и бинарный upload/download через ProxyJump и ProxyCommand. В варианте ProxyCommand проверены кавычки и пробелы в пути конфига.
- Проверены отказ неизвестного/изменённого ключа конечного сервера и jump-узла, отказ авторизации и запрещённое перенаправление. Отмена зависшего ProxyCommand и закрытие успешных proxy-сессий проверяют завершение дочерних процессов через Windows process handles.
- `TestShutdownReapsProxyDuringHandshake`: закрытие сервиса при зависшем ProxyCommand завершает операцию с `context.Canceled`, сам proxy-процесс и его дочерний процесс.
- Повторно пройдены тесты прямого SSH/SFTP и оценки `ssh -G` через общий запускатель. Алиасы с shell-символами отклоняются при обнаружении и при подключении.

Общий запускатель создаёт Windows-процесс приостановленным, назначает Job Object до выполнения и ждёт завершения группы при отмене, ошибке и закрытии. SFTP stdout и диагностический stderr разделены; конфиг и его команды не переписываются и не выводятся в сообщения ошибок. Тестовые серверы и файлы изолированы; ACL изменяется только у временных тестовых файлов.

Ограничения: параметры конечного сервера не наследуются jump-узлами; строгая проверка их ключей, BatchMode и отключение ControlMaster/ControlPath должны быть заданы в доверенном SSH-конфиге. Произвольный ProxyCommand задаёт собственную политику промежуточного клиента. В Windows OpenSSH 9.5 путь альтернативного конфига с пробелами некорректно передаётся во внутреннюю команду ProxyJump: для него использован путь без пробелов, ограничение документировано. Ручная проверка окна/рабочей сети и ноутбука пока не выполнена; тест shutdown проверяет сервис, а не визуальное закрытие Wails-окна. Подробности: [proxy-connections.md](proxy-connections.md).
