# Авторизация по паролю

В настройках сервера выберите способ авторизации «Пароль», сохраните настройки и подключитесь. OpenSSH запросит пароль через отдельный диалог приложения. Диалог работает и во время предпросмотра или выполнения очереди; отмена останавливает подключение.

В JSON сохраняется только `connection.authMode: "password"`. Сам пароль не попадает в настройки, резервные копии, аргументы процесса или переменные окружения. Приложение передаёт ответ через временный локальный канал SSH_ASKPASS. Пароль обрабатывается в памяти приложения и OpenSSH; гарантированного стирания всех копий из памяти Go/JavaScript нет.

Галочка «Сохранить пароль» сохраняет его после успешного SSH/SFTP-входа в Диспетчере учётных данных Windows (generic credential, локальное постоянное хранение для текущего пользователя). Следующие соединения, предпросмотр и очередь используют его без диалога, в том числе после перезапуска. Без галочки ответ используется только для текущего подключения. Отмена и неудачный вход ничего не сохраняют. Галочка относится только к распознанному вопросу OpenSSH о пароле; passphrase/OTP не сохраняются этим механизмом.

Пароль привязан к снимку параметров `Connection` и тексту SSH-запроса. Разные host/user/port/alias/config/key/known_hosts не используют один и тот же сохранённый ответ; изменение root path, маппингов или имени проекта не меняет пароль. Идентичные параметры подключения в разных проектах используют общую запись текущего Windows-пользователя. Внешний доверенный SSH-конфиг определяет адреса алиасов и прокси как прежде.

Если OpenSSH повторяет вопрос после подставленного пароля, отклонённая запись удаляется и появляется диалог нового ввода. «Забыть сохранённый пароль» в настройках удаляет записи текущих сохранённых SSH-параметров. Уже открытая сессия остаётся авторизованной до отключения; следующий вход потребует ввода. Устаревшие записи для ранее изменённых параметров можно удалить через Диспетчер учётных данных Windows; записи приложения имеют префикс `SFTPProjectManager/`.

Хранилище шифруется средствами Windows и привязано к текущей учётной записи на компьютере. Portable ZIP и папка `data` не содержат сохранённые пароли. На другом компьютере/под другой учётной записью нужен повторный ввод. Это защита хранения на диске, а не от программ, уже работающих с правами того же Windows-пользователя. Основа: [Windows Credential Manager](https://learn.microsoft.com/en-us/windows/win32/secbp/handling-passwords).

Отсутствующий `authMode` сохраняет прежнее поведение: ключ или SSH-agent, `BatchMode=yes`. Режим пароля использует `BatchMode=no`, только password authentication, до трёх попыток. Проверка known_hosts остаётся строгой; неизвестный или изменившийся ключ сервера не подтверждается диалогом пароля.

Пароли промежуточных узлов через ProxyJump/ProxyCommand зависят от доверенного SSH-конфига: `BatchMode=yes` на узле запрещает запрос пароля. Команды стороннего ProxyCommand могут иметь собственный механизм авторизации. Сохранение выполняется только по галочке пользователя; SSH-конфиг не изменяется.

Passphrase зашифрованного ключа и MFA — следующие отдельные сценарии. До их проверки используйте SSH-agent для зашифрованных ключей.

Основа механизма: [SSH_ASKPASS и SSH_ASKPASS_REQUIRE в документации OpenSSH](https://man.openbsd.org/ssh). Вспомогательный режим запускается тем же portable exe до инициализации Wails и чтения настроек.
