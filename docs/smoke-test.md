# Ручная проверка portable-приложения

## Предпросмотр, сравнение и быстрый поиск (новая панель)

ПКМ локальной папки → `Mark directory excluded`: проверить подпись в дереве и отсутствие её файлов в Ctrl+Shift+N, включая нераскрытые вложенные папки. Снять пометку через `Unmark directory excluded`, проверить возврат результатов. Перезапустить приложение: ручные пометки сохраняются. В новом проекте проверить автоматическую пометку `.idea`, `.cache` и вложенных dot-папок; снятие пометки конкретной dot-папки также сохраняется.

1. Открыть локальный файл двойным кликом и Enter: проверить номера строк, Unicode и отображение кода как текста. Открыть файл на сервере: имя вкладки содержит сервер. Переключить сервер; обновить старую вкладку — читается исходный сервер.
2. ПКМ по одному файлу: сравнить с default-сервером и отдельно выбрать другой. Проверить mapping подпапки, обе версии и подсветку добавления/удаления строки; сервер в удалённом дереве не меняется. Для папки, исключённого файла и нескольких выбранных файлов сравнение недоступно.
3. Ctrl+Shift+N: найти файл в нераскрытой локальной папке, проверить нечувствительность к регистру и последовательность символов имени. Стрелки/Enter открывают выбранный результат, Escape закрывает поиск. Исключённые папки и ссылки в результаты не попадают.
4. Открыть бинарный файл, текст более 2 МиБ и файл более 10 000 строк: проверить пометки ограничений и отсутствие зависания. Отменить удалённое чтение при недоступном сервере; при password-авторизации проверить диалог и отсутствие сохранения содержимого в data.

## Основная portable-проверка

Основной сценарий на целевом Windows x64 проверен пользователем: приложение запустилось обычным пользователем, upload/download работают, соединение через ProxyJump с двумя промежуточными узлами установлено. Остальные пункты ниже — расширенный checklist portable-поставки; их статус не подтверждён и остаётся открытым.

1. Распаковать ZIP в доступную папку, например `Документы/Тест SFTP`. Запустить exe без повышения прав. Записать версию Windows и наличие WebView2.
2. Проверить отображение окна; платформу, OpenSSH и пути `data` посмотреть в диагностике настроек (либо через exe --diagnostics). Отсутствующий SSH не должен мешать открытию окна и созданию локального проекта.
3. Создать локальный проект с названием и папкой, закрыть окно, открыть снова. Проект и локальное дерево должны восстановиться; повторное сохранение настроек должно создать `settings.json.bak` с предыдущими настройками.
4. Запустить exe из другой рабочей директории: данные должны остаться рядом с exe. Проверить создание файлов в `data/webview2`.
5. Повторить запуск на машине без Go/Node.js. Наличие этих инструментов не должно требоваться.
6. На тестовой копии приложения, закрыв окно, испортить `settings.json`. Следующий запуск должен показать ошибку и сохранить повреждённый файл. Восстановить его из резервной копии вручную.
7. В изолированной среде без WebView2 проверить понятную ошибку, отсутствие установки runtime и запроса UAC. Не удалять runtime на рабочем ноутбуке ради проверки.
8. Проверить недоступную для записи папку в тестовой среде: приложение должно сообщить о необходимости переноса, без скрытого сохранения в другую папку.

Записать дату, Windows/архитектуру, путь распаковки и результаты каждого пункта. SSH-авторизация, ProxyJump и передача файлов относятся к следующим этапам.

## Проверка вертикального среза

Выполнять только с тестовым сервером и тестовыми файлами.

1. Создать локальный проект, затем в настройках добавить сервер: удалённая папка, алиас или manual host/user/port. Сохранить, перезапустить, проверить восстановление полей. Автоподключения быть не должно.
2. Подключиться с ключом/агентом и уже проверенным ключом сервера. Проверить листинг и открытие подкаталогов обеих панелей.
3. Загрузить бинарный файл, скачать его в тестовом проекте, сравнить SHA256 через `Get-FileHash`. Для перезаписи дать явное разрешение в предпросмотре.
4. Повторить без разрешения перезаписи: пакетный UI должен пропустить существующий файл и сохранить его прежнее содержимое. Старый одиночный API сохраняет прежний отказ вместо пропуска.
5. Проверить неизвестный/изменённый host key в отдельном тестовом known_hosts: подключение должно остановиться. Проверить ошибку неверного пользователя и недоступного сервера.
6. Проверить файл вне маппинга, ссылки/junctions, существующий каталог вместо файла, отсутствие родительского каталога и прав записи. Передача должна отказать без удаления цели.
7. Передать большой тестовый файл и отменить операцию; затем закрыть приложение во время другой передачи. Проверить отсутствие оставшегося ssh.exe этого приложения. Проверить сообщения о временных файлах, если соединение оборвалось до очистки.

ProxyJump и ProxyCommand проверяются по отдельным пунктам ниже. Проверка рабочего ноутбука и ручного UI остаётся открытой до отчёта пользователя.

## Выбор локальной папки

1. Нажать «Выбрать папку…» рядом с локальным корнем. Проверить стандартный диалог Windows и начальную папку, если в поле уже указан существующий абсолютный путь.
2. Выбрать тестовую папку с кириллицей и пробелами. Абсолютный путь должен появиться в поле; ручное редактирование должно работать. Настройки на диске меняются только после создания проекта/сохранения настроек, SSH не запускается.
3. Снова открыть диалог и отменить. Прежний путь должен остаться. Проверить открытие диалога с пустым и несуществующим путём в поле.
4. Выбор junction/папки внутри junction должен показать ошибку и сохранить прежнее поле. Проверить также отказ при ручном вводе такого корня и сохранении.

Ручная проверка этих пунктов ещё не выполнена.

## Несколько проектов и маппингов

1. Открыть тестовую копию со старым `settings.json` схемы 1 или 2. Проверить восстановление проекта/подключения/маппингов. Сохранить проект и проверить схему 3 и резервную копию прежнего файла; запуск без сохранения не должен менять исходник. Не тестировать миграцию на единственном экземпляре рабочих настроек.
2. Создать два проекта с разными локальными папками. В первом добавить два подключения к тестовым серверам с разными именами. Для одного подключения задать `rootPath: /srv/site` и два непересекающихся маппинга, например `src → public/src`, `assets → public/assets`; каталоги должны существовать.
3. Сохранить и переключить проект/сервер/маппинг. Деревья должны очиститься, SSH должен запускаться только по явной загрузке удалённого корня. Проверить сервер и оба корня над панелями; выполнить передачу тестового файла на каждом сервере и сравнить результат.
4. Перезапустить приложение. Проверить список проектов, подключения, маппинги и активный выбор. Проверить ручную передачу из выбранного подкаталога; корень дерева должен совпадать с выбранным маппингом без возможности выхода выше.
5. В черновике изменить поле: переключение сохранённого проекта/сервера блокируется до сохранения или отмены изменений. Добавление/удаление подключения и маппинга меняет только черновик до сохранения.
6. Проверить отказ пересекающихся маппингов: `src` и `src/nested`, локальный путь с другим регистром, назначения `public` и `public/nested`. Пары `src`/`src2` и `public`/`public2` должны приниматься. Путь `../outside` должен отклоняться.

Ручная проверка с двумя реальными серверами ещё не выполнена.

## Корень сервера и маппинги (новая схема)

1. Создать сервер с `rootPath: /var/www/html` и маппингом `src → .`. При выборе сервера удалённое дерево должно открываться от `/var/www/html`; корень не меняется при переключении маппинга.
2. Добавить маппинг `assets → static`. Убедиться, что его назначение — `/var/www/html/static`, а просмотр `/var/www/html` и соседних unmapped-папок доступен независимо от активного маппинга.
3. Передать файл внутри `src` в обе стороны и проверить сохранение относительной структуры. Передача unmapped-пути должна завершиться понятным отказом; выбор, охватывающий несколько маппингов, также отклоняется.
4. На копиях схем 1 и 2 проверить, что общий предок прежних абсолютных `remotePath` становится `rootPath`, а вычисленные назначения сохраняются. До первого сохранения исходный JSON не меняется; при сохранении создаётся резервная копия.

## Импорт SSH-алиасов и оценка настроек

1. Использовать тестовый SSH-конфиг: конкретные `Host`, маски, отрицательные шаблоны, повторные алиасы и `Include` с несколькими файлами/пробелами. Нажать «Прочитать SSH-алиасы»: показать конкретные имена, источники и предупреждения; проект и пользовательский SSH-конфиг не должны измениться.
2. Выбрать алиас. Проверить его в поле ручного ввода и абсолютный путь конфига в черновике. Сохранить проект, перезапустить, проверить восстановление. Выбор/чтение не должны запускать SSH.
3. Проверить альтернативный конфиг с относительным `Include`: поиск идёт от пользовательской `.ssh`, не от папки альтернативного конфига. Проверить цикл, отсутствующий файл, неподдерживаемую подстановку и условные Include — должны быть предупреждения.
4. На тестовом конфиге с безвредным `Match exec`, создающим временный маркер, проверить: чтение алиасов не создаёт маркер; «Проверить эффективные настройки» недоступна до подтверждения доверия; после явного запуска маркер появляется, UI показывает hostname/user/port/IdentityFile и параметры прокси без текста команд.
5. При долгой тестовой команде отменить оценку и отдельно закрыть окно во время оценки. Проверить завершение дочерних процессов этого приложения, понятное сообщение об отмене/таймауте и возможность последующей проверки. Не использовать разрушительные команды для тестирования.

Ручная проверка UI пока не выполнена.

## ProxyJump и ProxyCommand

Использовать тестовые серверы, ключи и конфиг по примеру [proxy-connections.md](proxy-connections.md). Для jump-узлов задать строгую проверку ключей, BatchMode и отключение ControlMaster/ControlPath. В Windows OpenSSH 9.5 путь конфига для ProxyJump должен быть без пробелов.

1. Сохранить SSH-алиас с ProxyJump через один узел, затем через цепочку из двух узлов. Проверить листинг и upload/download бинарного файла со сравнением SHA256.
2. Повторить с ProxyCommand. Проверить явно заключённые в кавычки пути программы/конфига с пробелами. Пользовательский SSH-конфиг не должен измениться.
3. В отдельном тестовом known_hosts проверить неизвестный/изменённый ключ конечного сервера и каждого SSH jump-узла: подключение должно остановиться. Проверить неверный ключ авторизации узла и недоступный узел.
4. Отменить подключение во время ожидания прокси и передачу большого файла; отдельно закрыть окно при подключении и передаче. Проверить завершение ssh.exe и команд прокси, созданных приложением, и возможность следующей операции после отмены.

Интеграционные тесты выполнены; ручная проверка окна и рабочей сети ожидается.

## Исключения подключения

1. В тестовом проекте создать `.git`, `node_modules`, `.env`, `keep.txt`, `src/debug.log`. У нового подключения проверить предложенные правила; у старого — отсутствие автоматического добавления правил.
2. Добавить `src/**/*.log`, сохранить, перезапустить. Проверить восстановление правил, пометку исключённых элементов на обеих панелях и отключённые кнопки. `keep.txt` должен передаваться как раньше.
3. Выбрать маппинг `src → /srv/app`: правило `src/**/*.log` должно блокировать удалённый `debug.log` при скачивании и локальный при загрузке. Правило другого подключения не должно влиять на текущий сервер.
4. Ввести `../outside`, `/absolute`, `bad**name` или отрицание `!file`: сохранение должно отказать с номером правила. Проверить ввод нескольких строк, пустой строки между правилами и завершающего переноса строки.
5. Подготовить передачу разрешённого файла, добавить исключающее его правило и сохранить: прежний предпросмотр должен исчезнуть. Для передачи убрать правило, сохранить и подготовить новый предпросмотр.

Ручная проверка UI ожидается; синтаксис и применение в backend проверены автоматически.

## Два дерева с ленивой загрузкой

1. Открыть сохранённый тестовый проект. Проверить две панели с корнями выбранного маппинга: при запуске и переключении нет автоматического SSH/чтения каталогов.
2. Загрузить локальный корень и удалённый корень кнопками обновления (отдельно проверить раскрытие корня). Раскрыть несколько вложенных папок одновременно; соседние папки остаются закрытыми. Проверить кириллицу, длинные имена и пустую папку.
3. Свернуть и раскрыть загруженную ветку. Содержимое должно появиться из кеша. Для удалённой ветки проверить это после отключения тестовой сети: повторное раскрытие кеша не должно требовать соединения.
4. Создать/удалить тестовый файл снаружи приложения. Нажать «Обновить» у родительской папки: список должен измениться, вложенные ветки сброситься, соседние раскрытые ветки сохраниться. Обновление корня сбрасывает все его вложенные ветки.
5. Вызвать ошибку чтения удалённой папки/отменить загрузку. Проверить снятие индикатора и блокировки действий, ошибку у папки и «Повторить загрузку». При ошибке обновления прежние данные помечены как ранее загруженные; после восстановления сервера повтор должен работать.
6. Проверить исключённую папку/файл и ссылку: они видны с пометкой, раскрытие и передача недоступны. Попытка доступа через backend по-прежнему отклоняется.
7. Выбрать обычный файл глубоко в дереве каждой панели. Предпросмотр должен показывать правильные сервер и полные пути. Передать тестовый файл; обновить ветку назначения вручную и проверить результат.
8. Сменить проект, сервер или маппинг; затем сохранить изменённые настройки. Оба дерева и предпросмотр очищаются. Новая загрузка использует выбранные корни и сервер. Проверить управление раскрытием/обновлением с клавиатуры (Tab, Enter/Space).

Ручная проверка окна и целевого ноутбука ожидается; автоматические тесты состояния не заменяют её. Контракт: [file-trees.md](file-trees.md).

## Постоянная сессия удалённой навигации

Проверить на Windows OpenSSH и тестовом сервере; при проверке считать реальные SSH-подключения. Не выполнять при запущенной очереди передач.

1. Запустить приложение, открыть проект и выбрать сервер. Убедиться, что SSH ещё не запускался. Явно прочитать удалённый корень, затем раскрыть несколько новых папок и обновить одну из них: все чтения должны использовать одну сессию.
2. Переключить маппинг того же подключения и прочитать дерево: сессия сохраняется. Переключить сервер или проект: старая сессия закрывается, а новая открывается только при явном чтении.
3. Проверить статус сессии и явное отключение. После отключения чтение открывает новую сессию; переподключение обновляет конфигурацию. Изменить SSH-настройки подключения, сохранить и убедиться, что следующее чтение использует новую сессию.
4. Оставить сессию без запросов более 10 минут: она закрывается. Во время медленного чтения дождаться 30-секундного таймаута или отменить запрос: сессия закрывается, следующий явный запрос создаёт новую.
5. Прочитать отсутствующую папку и папку без прав: ошибка показывается у ветки, а следующее чтение существующей папки сохраняет рабочую сессию. Отдельно оборвать SSH-соединение или получить EOF: следующая попытка должна создать новую сессию.
6. Запустить пакетную передачу. Пока очередь выполняется, навигация недоступна; сессия передачи остаётся независимой от сессии дерева. Отмена передачи не должна закрывать простаивающую сессию навигации. Проверить также закрытие приложения во время чтения и передачу через ProxyJump/ProxyCommand.

Ручная проверка постоянной сессии, таймаутов и состояния UI ожидается. Контракт: [remote-navigation.md](remote-navigation.md).

## Множественный выбор и рекурсивная передача

Использовать только тестовые проекты/серверы. Общий контракт: [batch-transfers.md](batch-transfers.md).

1. Подготовить папку с двумя вложенными уровнями, несколькими бинарными/текстовыми файлами, пустой папкой, `.env`, исключённой папкой и ссылкой. Отметить папку без раскрытия дерева и отдельный файл вне неё. Построить план: нераскрытые потомки должны присутствовать, исключённая папка/ссылка — только как пропуск без обхода, файлы/объём и оба пути — корректны.
2. Отметить родительскую папку вместе с её ребёнком и тот же файл повторно. В плане каждый относительный путь должен встречаться один раз. Выбор корня относится только к текущему маппингу. Сворачивание сохраняет выбор; обновление очищает выбор панели и предпросмотр.
3. Отменить предпросмотр. Проверить, что на стороне назначения ничего не создано. Повторить план и выполнить загрузку, затем скачивание в отдельный тестовый корень. Пустые папки и отсутствующие родители создаются; сравнить хеши бинарных файлов через Get-FileHash.
4. Создать существующий целевой файл с другим содержимым. Без разрешения перезаписи он должен быть пропущен, остальные файлы переданы. С новым планом и явным разрешением проверить замену. Конфликт «файл вместо папки» и «папка вместо файла» должен отказать ещё при предпросмотре.
5. Изменить источник или существующую цель, либо создать новую цель после предпросмотра. Выполнение должно отказать для изменённого элемента, сохранить цель и показать результаты остальных. Разрешение перезаписи не отменяет эту проверку.
6. Для подключения без исключений `.env` построить план с `.env`/`.env.production`. Начало заблокировано до отдельного явного разрешения. Подтверждение не должно обходить исключения: исключённые env-файлы остаются пропусками. После нового предпросмотра разрешения снова сняты.
7. Проверить недопустимое Windows-имя и пару серверных имён с коллизией регистра внутри ещё отсутствующей локальной папки. План должен отказать без создания папок/файлов. Проверить отказ пути через symlink/junction, включая промежуточный компонент назначения.
8. Передать большой пакет, отменить в процессе. Проверить таблицу результатов: готовые элементы остаются готовыми, оставшиеся — отменены; ошибки очистки временных файлов сохраняют подробности. Уже созданные файлы/папки не откатываются. Повторить только явно выбранные элементы через новый план.
9. При сохранении/смене проекта, сервера или маппинга выбор и предпросмотр очищаются. Последний выполненный результат остаётся привязанным к прежнему серверу и полным путям назначения. Сохранение изменённых исключений аннулирует прежний план; токен нельзя выполнить дважды.
10. Закрыть тестовое приложение во время предпросмотра и отдельно во время передачи. Проверить завершение созданного дерева SSH-процессов и отсутствие скрытой повторной операции при следующем запуске.

Ручная проверка окна и целевого ноутбука ожидается. Процент прогресса и очередь нескольких пакетов относятся к следующему пункту.

## Рабочее окно по модели PhpStorm

Актуальный первый сценарий описан в [ide-workspace.md](ide-workspace.md); для нового интерфейса использовать его вместо старого обязательного создания профиля с сервером.

1. На тестовой копии без settings.json открыть приложение. Создать проект с названием и локальной папкой через диалог Windows. Проверить, что SSH-поля не требуются; JSON содержит проект с connections: [], слева загружено дерево всей папки, справа пустая область сервера. Закрыть/открыть приложение: проект и корень восстановлены, SSH не запущен.
2. Открыть настройки из правой области и добавить первый SSH/SFTP-сервер, указав имя, авторизацию и удалённую папку. Сохранить: сервер появился в списке и стал default, SSH ещё не подключался. Явно подключиться: дерево справа должно начинаться от указанной удалённой папки.
3. Добавить второй сервер, назначить его default, сохранить и перезапустить. Проверить defaultConnectionID и сохранённый явный выбор. Открытие другого проекта и возврат выбирает default. Переключить сервер: справа меняется удалённый корень, слева остаётся полный тот же проект, исключения соответствуют выбранному серверу.
4. Для одного сервера выбрать локальный маппинг src. Слева по-прежнему видна вся папка проекта. Передача src/file.txt должна отправлять file.txt относительно удалённого корня; выбор файла рядом с src или корня проекта должен отказать с понятной подсказкой. Скачивание должно сохраняться в projectRoot/src.
5. Открыть настройки, изменить имя/папку/сервер и нажать отмену либо Esc: сохранённый проект не меняется, фокус возвращается к открывшей кнопке. Снова открыть: несохранённые изменения не должны остаться. После отмены создания нового проекта настройки прежнего проекта открываются как настройки, а не мастер создания.
6. В настройках проверить импорт SSH-алиасов, доверенную оценку, ProxyJump/ProxyCommand, маппинги и исключения. Изменение алиаса/пути конфига или выбранного сервера сбрасывает прежнее подтверждение доверия. Во время операции кнопка отмены доступна внутри модального окна; Esc/закрытие не должны скрывать незавершённую операцию. Ошибка сохранения/проверки видна внутри окна.
7. Удалить активный/default сервер: выбор безопасно переходит к оставшемуся; удалить последний: остаётся локальное дерево без передачи. Затем снова добавить сервер и проверить default. Файлы на обеих сторонах не удаляются.
8. Открыть старые настройки схемы 2 без defaultConnectionID: default становится первым сервером в памяти, исходный файл не переписывается только от запуска. Явно выбранный сервер сохраняется. Проверить также миграцию схемы 1 и резервные копии при сохранении.
9. Проверить два независимых скролла деревьев, окно 1280×800 и минимум 960×640, длинные пути/имена, много файлов, клавиатурный выбор и модальные формы. Рабочая область не должна превращаться в страницу с большой формой над деревьями.
10. Повторить пакетную передачу, env-подтверждение, skip/overwrite, отмену и частичные результаты: предпросмотр открывается отдельно, результаты доступны в нижней панели и сохраняют прежние сервер/полные пути после переключения.

Браузерная проверка make verify-ui использует только тестовый мост и не заменяет настоящий диалог Windows, SSH или рабочий ноутбук. PNG сохраняются в dist/ui-review, в portable ZIP не включаются.

## Очередь передач — ожидает ручной проверки

1. Добавить два подготовленных пакета для разных серверов. Проверить FIFO-порядок, сохранённые серверы и пути, прогресс байтов текущего файла и задания, а также счётчик обработанных элементов.
2. Запустить первое задание и поставить очередь на паузу. Текущая передача должна завершиться, следующее задание — остаться ожидающим. Пока пауза включена, добавить ещё пакет и затем продолжить очередь.
3. Во время работы проверить, что удалённое дерево и обычный предпросмотр недоступны, а локальное дерево, проекты и настройки доступны.
4. Отменить одно ожидающее задание и отдельно выполняемое. Проверить сохранение уже завершённых файлов, видимый статус отмены и сообщение об ошибке очистки временного файла, если она возникла.
5. Изменить источник или удалённое назначение после постановки в очередь. При запуске устаревший план должен завершиться видимой ошибкой и потребовать нового предпросмотра.
6. Повторить только неудачные/отменённые пути. Убедиться, что предпросмотр использует сервер исходного задания даже после смены активного сервера; подтверждения перезаписи и `.env` запрашиваются снова.
7. Очистить завершённые задания, убедившись, что ожидающие и выполняемые остаются. Проверить ограничение в 50 записей и потерю очереди после закрытия приложения.
8. Закрыть приложение при выполняемой и ожидающей передаче. Проверить отмену и завершение очистки SSH до закрытия окна.

## Выделение строк и меню передачи (ручная проверка)

1. В обоих деревьях нажать на имя папки: выделение меняется, папка не раскрывается. Проверить раскрытие/сворачивание отдельной стрелкой, включая сохранение вложенного выбора.
2. Выделить файл кликом, добавить папку через Ctrl и диапазон через Shift. Проверить Enter/пробел, недоступность ссылок и исключённых строк.
3. Нажать ПКМ на выбранной строке: весь выбор сохраняется. ПКМ на другой строке выбирает только её. Проверить Escape и клик снаружи меню.
4. Проверить быстрые действия с именем сервера по умолчанию и подменю другого сервера для upload/download. Предпросмотр показывает правильные пути, активный сервер дерева не меняется. Для одного сервера подменю отсутствуют.
5. Проверить оба действия из обеих панелей, маппинг с локальной подпапкой и отказ при выборе вне маппинга либо в нескольких маппингах. Запись начинается только после подтверждения плана.

## Парольная авторизация (ручная проверка)

1. В настройках сохранённого сервера выбрать «Пароль при подключении». Подключиться: диалог появляется поверх окна, поле скрывает ввод, SSH продолжает работу после подтверждения.
2. Проверить неверный пароль, повторный ввод и отмену кнопкой/ Escape. Отмена прекращает подключение и не открывает следующие запросы.
3. Пройти по вложенным папкам: действующее соединение не запрашивает пароль снова. После отключения и нового подключения пароль запрашивается.
4. Выполнить предпросмотр и передачу через очередь: запрос доступен во время занятой операции; пароль не запоминается для следующего соединения.
5. Проверить settings.json и резервные копии: только authMode, секрет отсутствует. Перезапустить приложение и убедиться, что пароль не восстановился.
6. Проверить установленный Windows OpenSSH, путь приложения с пробелами/кириллицей, обычного пользователя и рабочую сеть. Для ProxyJump проверить конфиг каждого промежуточного узла; BatchMode yes на узле запрещает ввод пароля.

## Сохранённый пароль и defaults (ручная проверка)

1. Создать новый сервер: корень `/`, маппингов нет. Сохранить и просмотреть удалённые папки; передача до ручного добавления маппинга недоступна.
2. Выбрать вход по паролю, в диалоге включить «Сохранить пароль» и успешно подключиться. После отключения, нового предпросмотра/передачи и перезапуска приложения пароль подставляется без диалога.
3. Ввести неверный пароль с галочкой: он не сохраняется. Для ранее сохранённого пароля, который перестал подходить, появляется новый диалог; правильный ответ с галочкой заменяет запись после успешного входа.
4. Нажать «Забыть сохранённый пароль», отключиться и подключиться: пароль запрашивается. Отмена даже с установленной галочкой не сохраняет ответ.
5. Убедиться, что settings.json, .bak и ZIP не содержат пароль. При запуске на другом компьютере/под другой Windows-учётной записью нужен повторный ввод.
