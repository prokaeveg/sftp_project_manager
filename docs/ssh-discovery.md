# Импорт SSH-алиасов

Краткий контракт для продолжения разработки. Системный и пользовательский SSH-конфиги приложение не изменяет.

## Чтение списка

`internal/sshconfig.Discover` читает указанный файл либо `%USERPROFILE%/.ssh/config`, возвращает абсолютный путь, конкретные положительные алиасы из `Host`, их исходный файл/строку и предупреждения. `Host *`, маски и отрицательные шаблоны не предлагаются как серверы. Ручной ввод алиаса остаётся доступным.

Чтение запускается кнопкой, без OpenSSH, shell или выполнения директив. Выбор алиаса заполняет черновик текущего подключения и сохраняет путь исходного конфига; проект сохраняется отдельной кнопкой.

`Include` поддерживает несколько файлов, абсолютные пути, `~/`, двойные кавычки и glob с лексическим порядком. Относительные пути считаются от пользовательской `.ssh`, включая случай альтернативного корневого конфига. Алиасы из условно включённых файлов показываются как кандидаты с пометкой; соответствие условий не вычисляется при чтении.

Ограничения чтения: глубина 16, 128 файлов, общий размер 2 MiB, строка 64 KiB, 4096 алиасов, 512 попыток обработки совпадений Include, 256 предупреждений. Циклы обнаруживаются по разрешённым путям с учётом регистра Windows. Неподдерживаемые подстановки `%...`, `${...}`, `~user`, одинарные кавычки и недоступные Include-файлы сообщаются предупреждениями. Команды из директив в предупреждения не выводятся.

Это обнаружение кандидатов, а не собственная реализация всей семантики OpenSSH. Неподдерживаемая при обнаружении директива остаётся в исходном конфиге и может обрабатываться OpenSSH при явной проверке или подключении.

## Эффективные настройки

`App.EvaluateSSH` требует явного подтверждения доверия конфигу и вызывает системный `ssh -G` для того же алиаса/конфига и подсистемы SFTP. Команды `Match exec` при этом могут выполняться; проверки условий и разрешение имён остаются поведением OpenSSH. Приложение не создаёт SSH-сессию для получения этих параметров.

UI показывает только hostname, user, port, пути IdentityFile, ProxyJump и наличие ProxyCommand. Текст команд и полный stdout/stderr не выдаются интерфейсу и не записываются в настройки. Показанные параметры не заменяют исходный конфиг и не переводят алиас в manual mode. ProxyJump/ProxyCommand используются при файловых операциях в режиме алиаса; контракт и настройки узлов описаны в [proxy-connections.md](proxy-connections.md).

Проверка ограничена 15 секундами и использует общую блокировку удалённой операции. Под Windows общий `startManaged` создаёт процесс приостановленным, включает его в Job Object с `KILL_ON_JOB_CLOSE`, затем возобновляет; наследуются только дескрипторы stdin/stdout/stderr. Отмена и закрытие окна завершают группу процессов, затем сервис ждёт окончания проверки. Тот же запуск используется для потоковой SFTP-сессии.

Оценка с управлением дочерними процессами реализована только для Windows; остальные сборки возвращают отказ вместо запуска команды без проверенного управления деревом.

## Навигация

`internal/sshconfig` — чтение и тесты; `internal/transport/evaluate*` — оценка; `internal/transport/process*` — управляемые процессы; `internal/application/ssh.go` — доверие/таймаут/отмена; `app.go` и `frontend/src/bridge.ts` — мост; `App.vue` — список и явная проверка.

Семантика сверена с официальными руководствами [ssh_config](https://man.openbsd.org/ssh_config) (`Host`, `Include`, `Match exec`) и [ssh](https://man.openbsd.org/ssh) (`-G`). Фактические проверки текущего Windows OpenSSH фиксируются в `verification.md`.
