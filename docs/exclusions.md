# Исключения подключения

Правила хранятся в `ProjectConnection.excludes` схемы 2. Поле необязательное: старые настройки загружаются без добавления правил и без перезаписи. Каждое подключение имеет собственный список, общий для его маппингов.

## Синтаксис

Путь считается от локального корня проекта даже для маппинга подкаталога. Для `src → /srv/app` правило `src/**/*.log` применяется к `/srv/app/debug.log`. То же правило применяется к скачиванию с сервера. Сравнение регистронезависимое на обеих сторонах, чтобы исключение не обходилось сменой регистра на Windows.

| Правило | Результат |
| --- | --- |
| `.git/**` | Корневая `.git` и все её потомки |
| `**/node_modules/**` | `node_modules` на любой глубине и все потомки |
| `*.log` | Имена с окончанием `.log` только в корне проекта |
| `src/**/*.log` | `.log` внутри `src` на любой глубине |
| `**/.env` | `.env` на любой глубине |
| `file?.txt` | `?` заменяет один Unicode-символ |

`*` не пересекает `/`; `**` допускается только как отдельный компонент пути и заменяет ноль или больше компонентов. Если исключён каталог, исключаются все его потомки. Правила закреплены за корнем: `cache` не означает любой каталог с таким именем; для этого нужно `**/cache`.

Это отдельный синтаксис, без совместимости с `.gitignore`. Нет отрицаний `!`, комментариев `#`, диапазонов `[]` или экранирования. Запрещены абсолютные пути, `\`, двоеточия, управляющие символы, компоненты `.`/`..`, пустые компоненты и пробелы по краям правила. Максимум 100 правил, каждое до 512 байт UTF-8. В UI пустые строки удаляются при сохранении, остальные проверяются backend с номером ошибочного правила.

## Применение

Исключённые файлы и каталоги видны в обеих панелях с пометкой; кнопки открытия/передачи отключены. Backend отдельно блокирует листинг исключённого каталога, подготовку upload/download и выполнение исключённого плана до запуска SSH. Изменение сохранённых исключений, удаление или замена существующего подключения аннулирует подготовленный предпросмотр. Уже выполняющаяся операция использует свой снимок; UI не позволяет сохранять настройки во время неё.

Для передачи исключённого файла нужно изменить правила, сохранить проект и подготовить новый предпросмотр; скрытого обхода правил нет. У новых подключений UI предлагает `.git/**`, `**/node_modules/**`, `**/.env`, `**/.env.*`. Последнее включает `.env.example`: при необходимости правило можно изменить. Старым подключениям эти значения не назначаются автоматически. В [массовой передаче](batch-transfers.md) исключённые потомки показываются с причиной пропуска и не обходятся. Включённые правилами `.env`/`.env.*` требуют дополнительного явного разрешения в текущем плане, проверяемого также backend.

## Навигация для агентов

- `internal/exclusion` — валидатор, сопоставление через динамическое программирование и тесты синтаксиса.
- `internal/config/store.go` — проверка при загрузке/сохранении и построение профиля с префиксом маппинга.
- `internal/application/projects.go`, `service.go` — сохранение, аннулирование предпросмотра, глубокие копии правил.
- `internal/application/files.go`, `exclusions_test.go` — применение и проверки отказа до SSH.
- `frontend/src/App.vue`, `bridge.ts` — редактор и пометки файлов.

Для продолжения достаточно этого документа и [agent-context.md](agent-context.md); полный план читать при изменении требований.
