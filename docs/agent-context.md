# Краткое состояние проекта

Обновлено: 6 октября 2026 года. Обновлять при существенных изменениях; хранить текущее состояние, а не историю переписки.

## Задача и ограничения

Разработка portable SFTP-менеджера по [основному плану](../sftp-project-manager-plan.md). Начать с этапа 0 и вертикального среза; ядро Go отделить от UI. Полный MVP пока не реализован.

Пользователь просит не использовать Superpowers. Дополнительные Markdown-файлы разрешены для экономии контекста; 6 октября разрешены субагенты на более дешёвых моделях. Не хранить секреты. Не считать проверку на машине разработки проверкой рабочего ноутбука.

## Текущее состояние

- Реализована основа этапа 0: Vue/Wails-окно, диагностика SSH/WebView2, сохранение названия для проверки JSON и portable-пути относительно exe.
- В репозитории есть `go.mod`: модуль `awesomeProject`, директива `go 1.26`.
- До начала работы уже имелось изменение `.gitignore`; не перезаписывать его без учёта пользовательских изменений.
- На момент первоначального поиска `AGENTS.md` в проекте не найден.
- Реализован первый вертикальный срез: один профиль и корневой маппинг, алиас/manual connection, локальные/удалённые списки, предпросмотр с одноразовым токеном и снимком профиля, upload/download одного файла, разрешение перезаписи, отмена и завершение процесса.
- Встроенного доверия новому host key нет: OpenSSH строго проверяет known_hosts, новый отпечаток подтверждается пользователем вне приложения. ProxyJump/ProxyCommand, управление деревом процессов, исключения и два дерева файлов реализованы. Множественный выбор и рекурсивная передача используют [пакетный план](batch-transfers.md) с результатами каждого элемента. Пароль/MFA, очередь нескольких заданий, процент прогресса и постоянный журнал ещё не реализованы.
- `internal/mapping`, `internal/transport`, `internal/transfer` дополняют сервис. Текущая схема настроек — 2 с `projects` и активными ID; схема 1 мигрирует без записи при загрузке. `profile` теперь отражает выбранный маппинг для файлового ядра, пересчитывается при загрузке и выборе. `bridge.ts` содержит актуальный узкий API, сверенный с генерацией Wails.
- Структура: `internal/config` (хранилище), `internal/application` (сервис), `app.go` (мост), `main.go` (Wails), `frontend/src` (Vue/TypeScript).

## Рабочие предположения и открытые вопросы

Рабочий стек из плана: Go + Wails v2 + Vue 3 + TypeScript; русский UI; OpenSSH-процесс и SFTP через stdin/stdout; JSON в `data` рядом с exe. Это предположения, а не новые подтверждения пользователя.

Поддержка обоих ProxyJump и ProxyCommand подтверждена пользователем 6 октября и реализована. Jump-узлы требуют собственной строгой политики в доверенном конфиге; параметры конечного сервера не наследуются. Windows OpenSSH 9.5 неправильно передаёт путь `-F` с пробелами во внутреннюю команду ProxyJump; использовать путь без пробелов. Контракт и пример: [proxy-connections.md](proxy-connections.md). Ответ о Windows/архитектуре рабочего ноутбука, наличии `ssh.exe` и способе авторизации пока не получен. Сведения о машине разработки не заменяют этот ответ.

## Ближайшие действия

1. Выбор локальной папки реализован 6 октября: `App.SelectLocalDirectory` вызывает Wails `OpenDirectoryDialog` с контекстом из `OnStartup` (отдельным от контекста SSH-операций), проверяет корень через `mapping.New`; кнопка подставляет путь только в черновик формы. Отмена сохраняет прежнее значение. Ручная проверка диалога ожидается. Учесть ответ о целевом ноутбуке, когда он поступит.
2. Выполнить ручной [smoke test](smoke-test.md): визуальный UI, сохранение через форму, обычный пользователь, отсутствие Go/Node и проверка рабочего ноутбука.
3. Сборка использует установленный WebView2 и режим `error`; Fixed Version Runtime ещё не поставляется. Не запускать автоматическую установку с повышением прав.
4. `.ps1` блокируется политикой текущего PowerShell; команды прямой сборки и упаковки приведены в README, политика не менялась.
5. Несколько проектов/подключений/маппингов, схема 2 и миграция без записи при загрузке реализованы: [projects.md](projects.md). Панели используют выбранный маппинг; переключение не подключается к SSH. Импорт SSH-алиасов/Include и отдельная доверенная оценка `ssh -G` реализованы: [ssh-discovery.md](ssh-discovery.md).
6. ProxyJump/ProxyCommand завершены: общий запускатель `internal/transport/process_windows.go`, тесты `proxy_integration_test.go` и `internal/application/proxy_shutdown_windows_test.go`. Проверены два jump-узла, бинарная передача, ошибки ключей/авторизации/сети, отмена и shutdown.
7. Исключения завершены: необязательный `ProjectConnection.excludes`, без смены схемы и добавления правил старым подключениям. Синтаксис `*`/`?`/`**`, пути от корня проекта, регистронезависимое сравнение; префикс маппинга — `Profile.ExcludeBase`. Исключённые элементы видны, открытие/передача блокируются в backend. Изменение правил аннулирует предпросмотр; правила копируются. Новые подключения предлагают исключения `.git`, `node_modules`, `.env`. Для контекста читать [exclusions.md](exclusions.md), не весь план.
8. Два дерева: [file-trees.md](file-trees.md). Состояние в `file-tree.ts`, рекурсивный `components/FileTree.vue`, интеграция в `App.vue`. Кеш до обновления, ошибка с повтором, сброс при смене выбора/сохранении; `work` сериализует UI. `make check` включает 8 frontend-тестов (Node 22.18+/24+); Vue проверяется сборкой. Ручной UI ожидается.
9. Пакетная передача: [batch-transfers.md](batch-transfers.md). Читать контракт и `internal/application/batch.go` вместо всего плана. `PreviewBatch` обходит выбор с одной сессией, без записи; `ExecuteBatch(token, policy, includeEnvironment)` выполняет одноразовый снимок последовательно, создаёт только запланированные папки и возвращает все результаты, включая отмену/ошибки очистки. Лимиты 10 000/64; снимки источников/целей, исключения/ссылки/Windows-коллизии, явный env-гейт и skip/overwrite. Совместимость одиночного API сохранена; токены хранятся в прежнем `pending`, поэтому изменение исключений аннулирует и пакет. Тесты `batch_test.go`, настоящий Windows OpenSSH — `batch_integration_windows_test.go`. UI хранит выбор отдельно по панелям и последний результат с неизменным сервером/путями. Следующее — очередь/прогресс/ручной повтор ошибок, затем постоянный журнал. Для оптимизации контекста не перечитывать историю проверок и весь план; открывать тематический документ и нужные файлы.
